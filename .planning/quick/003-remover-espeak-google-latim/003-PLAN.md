# Quick Task 003: Remover eSpeak e priorizar Google Translate para Latin

## Objective

Remover o caminho dependente de eSpeak NG do fluxo Latin MVP e priorizar Google Translate para traduções em Latin, mantendo ElevenLabs italiano e FineVoice registrados como reservas/candidatos de áudio sem falsificar metadados de áudio já gerado.

## Approach Context

User confirmed: Google Translate should be the primary translation path for Latin. For audio, ElevenLabs Italian and FineVoice should be treated as reserves; FineVoice is not currently implemented in the project, so this quick task will register policy/candidate metadata rather than add a new live API integration.

## Codebase Context

The project is Python 3.12+, CLI-first, with provider adapters under `src/multilang/services/` and tests under `tests/`. Google Translate already exists in `provider_text_adapters.py` through `deep-translator`; ElevenLabs already exists as a modern-language TTS adapter with Italian locale/default voice. Latin MVP currently uses committed assets under `data/latin_mvp/`, frozen translation QA in `latin_translation_quality.py`, and eSpeak NG only for Latin audio sample generation/policy via `espeak_ng_speech_adapter.py` and `latin_audio_samples.py`. Existing generated Latin audio metadata must not be relabeled to a different provider unless the media is regenerated by that provider.
