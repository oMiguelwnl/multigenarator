# Quick Task 260421-001: implement Tatoeba as a filtered secondary sentence source with advanced reranking and validation, never as the raw default primary source - Context

**Gathered:** 2026-04-21
**Status:** Ready for planning

<domain>
## Task Boundary

Implement Tatoeba as a secondary source of example-sentence candidates. It should only enter the flow as a fallback and must never become the raw default primary source.

</domain>

<decisions>
## Implementation Decisions

### Fallback policy
- Tatoeba should be consulted only when the primary sentence path fails or routes an item toward review.

### Scope of Tatoeba data
- Tatoeba should provide only the example-sentence candidate. Translation remains on the existing separate translation path.

### the agent's Discretion
- Choose the exact fallback trigger, filter heuristics, and reranking structure as long as Tatoeba remains secondary-only and advanced filtering/reranking happens before any sentence is accepted.
- Prefer minimal changes that fit the existing Phase 3 text-generation and validation architecture.

</decisions>

<specifics>
## Specific Ideas

- Reuse the exploratory heuristics already tested in-session: prefer declarative sentences, direct translations present, reasonable token length, and reject obvious imperatives/questions/short fragments.
- Keep Tatoeba integration behind a clear service boundary so later provider-backed generation can coexist with it cleanly.

</specifics>
