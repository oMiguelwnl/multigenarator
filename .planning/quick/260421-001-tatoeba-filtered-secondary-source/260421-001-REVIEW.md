## Warnings

### WR-01: Generic runtime term templates are now guaranteed to fail validation

**File:** `src/multilang/runtime.py:77-85`, `src/multilang/services/text_validation.py:206-218`, `src/multilang/services/text_validation.py:354-356`
**Issue:** The runtime still emits generic term-template sentences such as `The word alpha is useful in daily life.`, but the validator now bans any sentence starting with prefixes like `the word`, `la palabra`, `le mot`, etc. That makes grounded items that take the `term` template path fail validation and land in review even when the rest of the pipeline is healthy. This regression is visible in `tests/integration/test_text_job_flow.py:139-175`, where accepted-item counts drop below the expected values.
**Fix:** Make the runtime `term` templates learner-friendly natural example sentences that can pass validation, or pass provenance into validation and apply the meta-sentence ban only to corpus fallback sentences instead of all generated text.

### WR-02: Related runtime/integration coverage is still failing after the fix commit

**File:** `tests/integration/test_text_job_flow.py:139-223`
**Issue:** The re-review verification run still has three failing assertions. Two failures come from the acceptance regression above, and the Spanish flow also still asserts an old persisted sentence (`Yo uso usar cada día.`) while the current runtime now stores `Es bueno usar cada día.`. The task therefore is not yet green end-to-end.
**Fix:** First resolve the runtime/validator incompatibility from WR-01, then update the Spanish integration expectation to the intended shipped sentence (or restore the prior runtime behavior) and rerun the related suite before marking the task complete.
