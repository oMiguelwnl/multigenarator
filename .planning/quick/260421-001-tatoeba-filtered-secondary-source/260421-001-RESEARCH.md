## Summary

Best fit: keep Tatoeba out of the top-level job orchestration and add it as a **secondary sentence-provider path used on the existing repair/fallback branch**. The current `GenerateTextItemsService` already does `generate -> validate -> repair once -> persist`, and today the repair branch just reruns the same generator again. Replacing that second attempt with a Tatoeba-backed candidate search is the smallest change that matches the locked policy. [VERIFIED: codebase read]

Primary translation should stay unchanged. The current architecture already generates translation from the chosen sentence, not from definitions, so a Tatoeba sentence can flow through the existing translation adapter and validator without turning Tatoeba into the translation source. [VERIFIED: codebase read]

Tatoeba should be treated as a candidate corpus, not a trusted source. Tatoeba publishes weekly downloadable exports, exposes sentence links/tags/base-translation structure, and explicitly notes that user sentence-review data is experimental; this supports using it for offline filtering/reranking, not raw acceptance. [CITED: https://tatoeba.org/en/downloads]

**Primary recommendation:** use Tatoeba only on the repair/fallback attempt, feed its selected sentence back into the existing translation + validation path, and accept it only if the normal validator passes. [VERIFIED: codebase read]

## Best Integration Point

1. **Keep `GenerateTextItemsService` as the control point for fallback policy.** It already decides when the first validation failed and when the one allowed repair attempt happens. [VERIFIED: codebase read]
2. **Add a source-aware sentence generation boundary in `TextGenerationService` or its sentence adapter layer, not in the repository or validator.** `TextGenerationService` already owns sentence generation before translation. [VERIFIED: codebase read]
3. **Use the repair branch for Tatoeba.** On first failure, do not call the same primary generator again; instead call a Tatoeba-backed candidate selector for the sentence, then run the existing translation adapter and `TextValidationService` on that result. [VERIFIED: codebase read]
4. **Do not couple Tatoeba to `_TemplateSentenceAdapter`.** Runtime templates are currently deterministic local fixtures used by shipped-path tests; embedding network/data lookup there would make those tests brittle. [VERIFIED: codebase read]

### Suggested flow

```text
primary sentence adapter
  -> validate
    -> pass => persist accepted
    -> fail => Tatoeba candidate search/filter/rerank
         -> best candidate
             -> existing translation adapter
             -> existing validator
                 -> pass => persist repaired/accepted
                 -> fail => persist review_required
```

## Initial Filter + Reranking Heuristics

### Hard filters
- Require target-language sentence text plus at least one linked translation in the learner translation language. Tatoeba exports direct sentence links and sentence-pair exports for language A/B. [CITED: https://tatoeba.org/en/downloads]
- Keep Tatoeba responsible only for sentence text; always discard Tatoeba translation text before deck generation and run the project's normal translation path. [VERIFIED: codebase read]
- Reuse the existing validator's hard checks after selection: target lemma/form presence, 4-12 token band, banned-pattern rejection, and translation mismatch detection. [VERIFIED: codebase read]
- Reject obvious questions immediately (`?`) and sentence fragments below the current minimum token threshold. The short-fragment part is already enforced; the question mark rule is a recommended add-on. [VERIFIED: codebase read] [ASSUMED]

### Reranking signals for MVP
- **Prefer original sentences** (`base = 0`) over sentences that are themselves translations. [CITED: https://tatoeba.org/en/downloads]
- **Prefer candidates whose linked translation is direct**, not indirect chain reuse. Tatoeba sentence pages can include noisy historical linking, so direct-link bias is safer than trusting graph depth blindly. [CITED: https://tatoeba.org/en/downloads] [CITED: https://tatoeba.org/en/sentences/show/1]
- **Prefer declarative punctuation** (`.`) over `?` or `!` when scores are close. Imperatives and prompts are overrepresented in generic corpora. [ASSUMED]
- **Prefer sentences where the matched target form is not the first token** and the sentence has a subject/article/context token before or after it; this is a cheap anti-imperative proxy. [ASSUMED]
- **Prefer mid-band length** around 5-9 tokens, because the current validator allows 4-12 and Phase 3 is locked to short learner-friendly examples. [VERIFIED: codebase read] [ASSUMED]
- **Down-rank reflexive mismatches**: if the display form is reflexive (`lavarse`, `se laver`), prefer candidates containing reflexive markers/pronouns over bare lemma-only matches. [VERIFIED: codebase read] [ASSUMED]
- **Down-rank meta/example-like content** similar to the validator's existing meta-sentence bans. [VERIFIED: codebase read]
- **Use positive sentence-review votes only as a soft bonus, not a hard gate, because Tatoeba marks review data as experimental.** [CITED: https://tatoeba.org/en/downloads]

### Minimal scoring shape

```text
score = 0
+ 3 if base == 0
+ 3 if target-form exact/reflexive-aware match
+ 2 if linked translation exists in target learner language
+ 1 if token_count in 5..9
+ 1 if endswith('.')
- 2 if contains '?'
- 2 if target token is first and sentence is short
- 3 if meta/template-like
```

Use deterministic scoring first; only add LLM reranking later if deterministic filters leave too many near-ties. [ASSUMED]

## Pitfalls to Guard Against

- **Imperative-heavy results:** a fallback corpus can over-return commands/prompts; current validation does not explicitly ban imperatives, so add a cheap pre-validator/reranker rule before acceptance. [VERIFIED: codebase read] [ASSUMED]
- **Reflexive false positives:** the validator already accepts inflected reflexive forms, but Tatoeba matching based only on lemma can still pick a non-reflexive usage for a reflexive study form. [VERIFIED: codebase read]
- **Translation misuse:** Tatoeba has translation links, but Phase 3 and the quick-task context both require translation to stay on the separate project path. Do not hydrate `translation_text` from Tatoeba. [VERIFIED: codebase read]
- **Runtime coupling:** `build_runtime_service()` currently wires deterministic template adapters for the shipped path; changing those adapters directly would spread Tatoeba logic into local/runtime tests. Inject a separate fallback-aware adapter instead. [VERIFIED: codebase read]
- **Overtrusting Tatoeba quality signals:** Tatoeba exposes native-speaker/reliability cues on sentence pages, but its downloadable user-review file is explicitly experimental, so these signals should only help ranking, not bypass validation. [CITED: https://tatoeba.org/en/sentences/show/1] [CITED: https://tatoeba.org/en/downloads]
