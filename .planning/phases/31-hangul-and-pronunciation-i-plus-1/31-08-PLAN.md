## Must-Haves

1. Exact fixed layout and canonical hashes are deterministic.
2. Qualified semantic, rights, and media validation is complete before receipt writing.
3. Every drift/failure path writes nothing.
4. Temporary fixtures prove success without becoming canonical evidence.

## Anti-Goals

- No actual evidence, checkpoint, CLI, canonical receipt/snapshot/pointer/export, live provider, or approval claim.

## Hard Boundaries

- README and receipt are excluded from canonical evidence-bundle input; receipt gets separate payload/file hashes.
- Archive/APKG magic, links/reparse points, devices/FIFOs, traversal, remote locators, extras, and unbounded files are rejected.
- Test fixture paths are private composition seams, never public arguments.
- No public `validate(...) -> object` plus `write(object)` split exists; the combined receipt operation owns one shared-lock critical section from fresh reads through atomic replacement.

## Evidence Contract

- Exact allowlist and one-to-one item/asset/role linkage tests.
- Complete approved-shaped temporary fixture success and missing/rejected/role-collapse/rights/media failure matrix.
- Atomic temp-receipt write tests and before/after tree hashes proving zero writes on drift.
- Public-surface tests prove forged validated/payload/receipt-shaped objects cannot enter any exported callable; phase-boundary hooks mutate evidence/prestate between private stages and must yield zero writes/no stale receipt.

## Common Pitfalls

- Implementing only presence checks instead of qualification and exact-byte checks.
- Including README/receipt in their own bundle/payload hash.
- Exposing a root option to make tests convenient.
- Exposing a separate writer that trusts an apparently validated caller object, or releasing the lock between validation and write.
- Copying approved-shaped fixture data into canonical paths.

## Stop-And-Challenge

- Stop on any arbitrary intake surface, unsafe filesystem object, write-before-validation, or attempt to treat fixtures as real evidence.
