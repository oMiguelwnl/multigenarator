## Requirements Covered

- **KHAN-01/02:** qualified Hangul/content/atomicity/media evidence becomes one exact inactive immutable bundle.
- **KPRO-01/02:** qualified phonetics/Portuguese/P0-P13/rights/playback evidence becomes part of the same receipt-bound bundle.

## Must-Haves

1. Only genuine directly placed fixed-schema evidence crosses the checkpoint.
2. User-confirmed index bytes bind canonical semantic validation.
3. Receipt and inactive snapshot writes occur only after complete validation.
4. Active pointer and export root do not change.

## Anti-Goals

- No evidence creation/repair, activation, export, publication, provider call, or visual/playback acceptance claim.

## Hard Boundaries

- The checkpoint does not accept a verbal blanket approval; it requires exact files from qualified sources and a 64-lowercase-hex confirmed index hash.
- The executor inspects and validates but never edits supplied evidence to make it pass.
- Preparation is inactive: an absent pointer stays absent and an existing pointer stays byte-identical.

## Evidence Contract

- The checkpoint response binds the exact index hash subsequently passed to validation.
- The receipt command accepts only that hash; all validation/payload/write state is freshly derived privately under one shared lock.
- CLI output records only aggregate counts/statuses and exact SHA-256 values, never source text, reviewer notes, absolute paths, or credentials.
- Before/after state captures prove receipt and one snapshot are the only allowed writes; receipt/preparation failure allows none, and `verify-prepared` allows none even on success.

## Common Pitfalls

- Treating the project user as every required specialist or rights authority.
- Passing the inspector's hash automatically without human confirmation.
- Calling a separate public validator/writer or passing an internal-looking validated object to receipt creation.
- Repairing a failed evidence file or substituting fixture bytes.
- Preparing and activating in one approval step.

## Stop-And-Challenge

- Stop at missing evidence, qualification ambiguity, hash mismatch, unsafe filesystem object, semantic failure, immutable collision, or any request to bypass the separate activation review.
