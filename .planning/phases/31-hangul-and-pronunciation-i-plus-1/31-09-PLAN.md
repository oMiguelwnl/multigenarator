## Requirements Covered

- **KHAN-01/02:** exact reviewed Hangul/media/strict evidence can form one immutable active bundle.
- **KPRO-01/02:** exact reviewed pronunciation/media/P0-P13 evidence uses the same atomic bundle and pointer.

## Must-Haves

1. Validation under lock precedes every recovery/write.
2. Drift produces zero writes, including no cleanup.
3. Snapshot hashes and immutable collision semantics are exact.
4. Prepared-state review has a pathless strictly no-write verifier.
5. Atomic activation and concurrent reads expose only complete state.

## Anti-Goals

- No canonical evidence/receipt/snapshot/pointer/export, CLI, human checkpoint, provider call, or production claim.

## Hard Boundaries

- Lock acquisition is the only operation before complete read-only validation.
- Snapshot manifest/root hashes are non-self-referential and deterministic.
- Private termination hooks cannot be reached through environment variables, CLI, or exported APIs.
- Prepared verification uses read-only opens/lstat/hash parsing plus end-of-operation identity/prestate rereads; it never acquires a lock in a mode that can create/touch lock state and never invokes a write-capable helper.

## Evidence Contract

- Call-order spies prove lock → all reads/validation → recovery → staging/write.
- Before/after trees prove every stale receipt/index/rights/reviewer/media/snapshot/pointer/prestate case writes nothing and leaves stale stages intact.
- With every write/recovery primitive monkeypatched to raise, valid `verify-prepared` still returns the exact tuple; missing/altered receipt, member, media, manifest, root, tuple, or recorded/current prestate fails with the tree byte-identical.
- Subprocess kill and injected failures prove old/new-only atomicity; reader loops prove no mixed bundle.

## Common Pitfalls

- Recovering stale staging before validating receipt authority.
- Creating snapshot root/staging directories before drift checks finish.
- Making the manifest hash self-referential.
- Accepting receipt hash alone without hash-bound activation authorization.
- Reusing `prepare-snapshot` as a review-time verifier, even if an exact-target branch is expected to be idempotent.

## Stop-And-Challenge

- Stop on any write-before-validation, mixed reader observation, collision overwrite, or public path/test-hook requirement.

## Approval Gates

- None. Authorization mechanics use fixture hashes only; real authorization is Plan 31-12.
