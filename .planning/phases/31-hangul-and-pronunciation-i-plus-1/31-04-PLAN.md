## Requirements Covered

- **KHAN-01:** orthography/content/media/license/playback gates for the complete Hangul pack.
- **KHAN-02:** curriculum/atomicity approval cannot override strict graph facts.
- **KPRO-01:** Portuguese, phonetics, and all three required audio slots are independently gated.
- **KPRO-02:** specialist approval is bound to exact pronunciation/rule evidence and active-rule hashes.

## Must-Haves

1. Missing evidence is valid pending state but never release approval.
2. Exact bytes, text, source versions, hashes, roles, and licenses must agree.
3. Production stays blocked and transient fixtures cannot contaminate it.

## Anti-Goals

- No media generation/acquisition, live provider, reviewer substitution, UI, template, or export writer.

## Hard Boundaries

- Use JSON/Pydantic and repository-relative filesystem checks only.
- Resolve the active pointer once at the operation boundary and pass the frozen resolved snapshot through review/media/export checks; never reread it mid-operation.
- Pending top-level manifests remain review inputs and can never satisfy production readiness.
- Prefer PCM WAV for reviewed audio because stdlib `wave` can inspect it offline.
- Reject script/event-handler markup and remote media; allow only bounded Anki media tags in designated fields.

## Evidence Contract

- Tests create deterministic non-empty WAV/image bytes only under `tmp_path`.
- Every approved-shaped fixture carries unmistakable test IDs and complete human-role/license metadata.
- Tests prove production files remain byte-identical and all production readiness calls fail.

## Common Pitfalls

- Approval keyed only by filename or provider success.
- One person filling specialist and independent-native roles.
- A path resolving outside the root after a superficial string check.
- Treating a sound tag or generated tone as production media.

## Stop-And-Challenge

- Stop on unsupported media format, unclear license disposition, missing reviewer role, or any request for an approval bypass.

## Approval Gates

- This plan defines gates; only the `checkpoint:user` in Plan 31-11 can supply canonical evidence, after Plans 31-08 through 31-10 have already implemented and fixture-proven validation, snapshot, CLI, and export machinery.
