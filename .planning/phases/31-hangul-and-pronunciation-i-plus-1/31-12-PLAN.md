- The review signal authorizes only the exact tuple displayed and the six exact local destinations; any tuple or prestate change requires a new review.

## Evidence Contract

- Pre-review uses only pathless `verify-prepared`; all write/recovery primitives remain forbidden and the command validates the existing receipt/snapshot/media/manifest/root/tuple/prestate directly.
- Activation output and `verify-active` prove receipt-to-snapshot-to-pointer provenance.
- `inspect-exports` opens APKG ZIP/media/SQLite and parses tabular fields/media/checksums against active IDs/hashes.
- Focused and complete offline tests run under Python 3.12 with no provider/importer surface and unchanged shared `.venv`.

## Common Pitfalls

- Treating a prepared snapshot as implicitly authorized.
- Calling `prepare-snapshot` or any repair/recovery path from the review checkpoint instead of the strictly read-only verifier.
- Reusing authorization after active-prestate drift.
- Exporting before active provenance is verified.
- Calling six file/directory presences a deep artifact inspection.
- Running the final proof in the repository's shared `.venv` or claiming static output as observed Anki acceptance.

## Stop-And-Challenge
