## Requirements Covered

- **KMODE-01:** canonical `ko` and persisted identity reach provider/cache boundaries.
- **KMODE-02:** changes are optional/additive for non-Korean requests.
- **KNLP-01:** NFC and analyzer fingerprint survive provider boundaries.
- **KNLP-02:** POS/sense/signature isolate homographs before generated text exists.

## Must-Haves

1. Persisted identity enters requests unchanged.
2. Structured identity determines prompt/cache isolation.
3. Provider text is canonical before cache or persistence.
4. LLM output remains subordinate to source morphology/sense.

## Anti-Goals

- No validation, runtime, network, audio, export, or UI work.

## Hard Boundaries

- No prompt-only workaround: identity must be a typed request field.
- No raw private highlight or vendor token dump in request, cache, telemetry, or errors.
- No DeepL Korean target mapping because Korean source cards target Portuguese.

## Evidence Contract

- Request/cache tests compare identities differing only by POS or sense.
- Prompt tests inspect Korean name and controlled identity evidence with redacted highlight context.
- Fake provider/cache tests prove NFC occurs before cache write and on cache restore.
- Existing non-Korean provider/grounding suites remain green.

## Common Pitfalls

- Adding identity only to prompt prose while cache keys remain surface-based.
- Normalizing after raw provider output has already been cached.
- Passing identity to sentence generation but not definition generation.
- Letting generated glosses overwrite source-backed sense.

## Stop-And-Challenge

- Stop on cache architecture drift, private data exposure, or any need for live provider capability.

## Approval Gates

- All tests are offline; no provider/network approval is granted.
