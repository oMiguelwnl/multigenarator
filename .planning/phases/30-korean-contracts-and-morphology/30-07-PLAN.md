## Requirements Covered

- **KMODE-01:** runtime/CLI expose canonical Korean through existing shared composition.
- **KMODE-02:** unavailable analyzer isolation and existing runtime/CLI regressions.
- **KNLP-01/02:** one fingerprint/matcher is shared by grounding, preview, generation, and regeneration.

## Must-Haves

1. One adapter object per composed runtime/app.
2. Lazy Korean-only failure.
3. Preview/ingestion resolver equivalence.

## Anti-Goals

- No content, audio, export, provider, or validation algorithm changes.

## Hard Boundaries

- Do not instantiate Kiwi in CLI handlers per call/card.
- Do not resolve full runtime providers for a count-only preview.
- Reuse injected services in tests and callers.

## Evidence Contract

- Runtime test checks Python object identity across grounding and both validation consumers.
- Unavailable factory test proves non-Korean construction/operation remains usable.
- CLI tests inject counting resolvers and prove local/WebDAV preview uses them once with no private output.

## Common Pitfalls

- Creating one adapter in grounding and another in `TextValidationService`.
- Making preview call `build_runtime_service()` and fail on unrelated provider credentials.
- Falling back to generic Korean extraction when no resolver exists.

## Stop-And-Challenge

- Stop if one-object composition or lightweight offline preview cannot be preserved.

## Approval Gates

- No provider, audio, export, or delivery action is approved.
