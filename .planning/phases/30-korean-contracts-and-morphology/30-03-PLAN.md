## Requirements Covered

- **KMODE-01:** canonical `ko` candidates, lookup paths, run keys, and rows retain one NFC identity.
- **KMODE-02:** additive nullable schema and backward-compatible index/candidate behavior protect existing languages and persistence.
- **KNLP-01:** typed lemma/POS/sense/signature/fingerprint evidence persists exactly.
- **KNLP-02:** source-backed POS/sense candidates make homograph-safe resolution possible and missing sense remains non-passing.

## Must-Haves

1. Source lexical candidates can represent multiple POS/sense records explicitly and can be enumerated deterministically for morphology/source binding.
2. Canonically equivalent Hangul converges before stable keys/hashes/persistence.
3. Typed identity survives a real ORM lifecycle.
4. Existing rows and constructors need no Korean data.
5. Migration topology and schema parity are provable.

## Anti-Goals

- No identity resolution algorithm or highlight extraction.
- No card/export schema expansion.
- No production Korean index or frequency data.
- No existing-row data migration beyond nullable column creation.

## Hard Boundaries

- Preserve submitted forms before NFC transformation.
- Keep structured identity authoritative; `lemma_key` remains an index/dedupe aid.
- Never put morphology evidence into `LexicalProvenance.notes` as a substitute for the typed JSON field.
- Use ORM expressions and validated JSON only; do not construct SQL from lexical forms or signatures.

## Evidence Contract

- Domain/lookup tests cover old and new index payloads, multi-sense records, stable full-record enumeration (including alias de-duplication without sense collapse), Portuguese policy, and identity consistency.
- Parser/fingerprint tests prove NFD/NFC convergence and submitted-form/order preservation.
- Repository tests commit, expire, reload, and compare the full typed identity/fingerprint.
- Migration tests prove unique head, upgrade, downgrade, named column presence, and ORM parity.

## Common Pitfalls

- Testing only the in-memory candidate returned before commit.
- Making `sense_id` mandatory globally and breaking existing lexical caches.
- Serializing `KoreanLexicalIdentity` with `str()` or parsing it from notes.
- NFC-normalizing submitted evidence instead of preserving it separately.
- Creating a second Alembic head without checking the execution baseline.

## Stop-And-Challenge

- Stop on migration-head drift or destructive migration requirements.
- Stop if any non-Korean cache fixture must be rewritten solely to satisfy Korean fields.
- Stop if implementation is tempted to pick the first of multiple source senses.
- Stop before touching export snapshot models/repositories.

## Approval Gates

- No data backfill, destructive migration, production sense source, or private-data persistence is approved.
- Any schema expansion beyond the one nullable JSON column requires explicit approval.
