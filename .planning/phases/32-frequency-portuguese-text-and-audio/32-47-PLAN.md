## Anti-Goals

- No manual SQL schema repair, downgrade, shadow migration, second Alembic head, destructive reset, or replacement of the SQLite development provisioning path.

## Hard Boundaries
- Use `.env` only through `uv run --env-file .env`; do not print environment values.
- All DB reads in preflight, guard, and post-validation must use SQLAlchemy/text statements or Alembic APIs; no SQL string interpolation from user input.

- Phase 33 schema DDL is included only because it is the current project head; no Phase 33 grammar/personal data workflow may run.
- If the target appears non-disposable at execution time, stop before connecting or before migration and return to the production-safe plan shape.

- Reintroducing the production backup/restore/rollback requirement into this disposable-only plan, or using this plan to waive that requirement for production.
- Applying only the old Phase 32 revision while the current runtime would later auto-apply `head`.
- Overclaiming Phase 32 completion from schema rehearsal without production DB, text, audio, review, export, release, or delivery evidence.
- Recording hostnames, usernames, database names, URLs, provider credentials, private paths, or raw SQL row content in evidence files.
