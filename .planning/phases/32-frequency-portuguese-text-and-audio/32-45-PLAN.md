# Phase 32 Plan 45: Pilot Command Scope and Job Binding Recovery

## Objective
Recover the executable command scope needed before a bounded text/catalog pilot can run: text-only `pilot_base` commands, explicit Phase 31 fallback verification, sanitized text-result output, read-only pilot evidence validation scope, and one local ignored DB job-binding proof. This plan deliberately stops before live providers, live Azure, audio, production DB work, export, release, or delivery.

This is an orchestrator-scoped, non-closing recovery prerequisite. It cannot and must not satisfy the full Phase 32 goal by itself.

## Context
- `.planning/ROADMAP.md` Phase 32 success criteria 4, 6, 8, and 9 require bounded text generation, manifest-bound final assets, deterministic validation, and observable provider routes before learner-ready closure.
- `.planning/phases/32-frequency-portuguese-text-and-audio/32-44-SUMMARY.md` says provider/editorial route-policy authority exists, but live pilot execution remains blocked by missing DB/job binding and command-scope authority mismatch.
- `src/multilang/domain/korean.py` already models `KoreanFrequencyJobAuthority(stage="pilot_base")`, where text/catalog pilot authority does not require catalog/profile/heard hashes.
- `src/multilang/cli.py` currently hardcodes `generate-korean-frequency-text` and `check-korean-frequency-job-binding` to full/audio-style authority and `validate-korean-provider-catalog-pilot-result` requires profile/heard inputs that its read-only authority model does not consume.
- Current Phase 31 pathless `verify-active` fails with `active_provenance_invalid`; Plan 32-44 recorded user-approved consumption of `31-32-SUMMARY.md`, `31-VERIFICATION.md`, `active-foundations.json`, and immutable snapshot receipt/manifest/root hashes as the bounded fallback.

5. Audio/full production paths remain blocked until separate authority exists.

- No provider calls, DeepL calls, Azure catalog query, Azure synthesis, production database connection/mutation, full production generation, text or audio review application, APKG build, release, Git action, publication, or delivery.
- No Phase 31 repair, active pointer rewrite, snapshot mutation, or new foundation approval claim.
- No new provider/model/fallback CLI flags; route identity remains policy-bound rather than command-line selected.

- Use TDD: write and run failing tests before production code changes.

- Solving the mismatch by inventing dummy profile or heard-review hashes. That would falsely grant audio/full authority.
- Treating the Phase 31 fallback as a generic bypass. It is valid only for the known current drift and exact approved artifacts.
- Writing a text result file that includes generated Korean, Portuguese text, prompts, completions, item keys, provider payloads, paths, or secrets.
- Letting command success imply provider spend, text quality, Azure voice availability, production DB readiness, exportability, or release readiness.
- Changing provider telemetry semantics broadly before the bounded pilot path exists.

- Stop if Typer option changes would remove existing full/audio command capability or allow ambiguous stage inference.
