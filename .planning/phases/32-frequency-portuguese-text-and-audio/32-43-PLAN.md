# Phase 32 Plan 43: Source Review and Final Bundle Recovery

## Objective
Replace the waived Phase 32 source-review and final-bundle gates with real, hash-bound evidence that later provider, database, text, audio, export, and release recovery plans can consume safely.

## Context
- `.planning/phases/32-frequency-portuguese-text-and-audio/32-VERIFICATION.md` reports `gaps_found`; source review, review receipts, aggregate, and final-bundle approval are absent or waived.
- `.planning/phases/32-frequency-portuguese-text-and-audio/32-42-SUMMARY.md` explicitly says Phase 32 must not be marked technically complete from waiver summaries alone.
- `.planning/phases/32-frequency-portuguese-text-and-audio/evidence-inbox/source-build-validation.json` validates the inactive bundle: 3000 accepted, 2965 rejected, 1000 per level.
- `.planning/AI-LINGUISTIC-REVIEW-POLICY.md` allows AI source/linguistic review when evidence is multi-pass, hash-bound, deterministic, and explicitly not human.

## Requirements Covered
- `KFREQ-01`, `KFREQ-02`, `GLEX-01`, `GLEX-02`, `GMOR-01`.

## Must-Haves
1. Source-review evidence covers every source disposition from the exact inactive bundle and does not expose source rows, private paths, prompts, credentials, or reviewer notes.
2. The source-review aggregate is generated from immutable receipts, not from waiver summaries or free-form prose.
3. The final-bundle checkpoint records an explicit decision for private local use and exact-byte redistribution before any production consumer may use the bundle.
4. This plan leaves Phase 32 blocked for production text/audio/export/release until later recovery plans provide their own evidence.

## Anti-Goals
- No provider calls, production database actions, Azure actions, synthesis, full run, APKG build, release, Git action, publication, or delivery.
- No Phase 33 review-command work, Phase 34 observed Anki proof, or v4/GUID/history work.
- No asset activation, commit, or publication from source-derived files.

## Hard Boundaries
- Touch only the plan-declared evidence files and summary.
- Do not modify `.multilang/phase32/bundles/multilang-korean-frequency-v1/`, `.multilang/phase32/source-quarantine/`, production assets, source code, tests, or roadmap status.
- Do not infer legal/source authority from NIKL page text, KOGL labels, source retrieval, build validation, AI review, or existing waivers.

## Evidence Contract
- `source-review-ai-consensus.json` must bind exact build/source/bundle hashes, policy ID/version, raw policy file SHA-256, actor type `ai_model`, `is_human=false`, per-pass provider/model/route/prompt/output-schema hashes, fresh-context independence scope, orchestration timestamps, deterministic validator IDs/versions/results/roots, controlled reasons, uncertainty codes, confidence, and coverage counts.
- `source-review-aggregate.json` must be serialized from the same service result returned by `validate_korean_bundle_review_batches` and independently checked by the CLI.
- `final-bundle-authorization.md` must validate as kind `final-bundle` through the checkpoint authority validator and grant no provider, DB, audio, full-run, release, Git, or publication power.

## Common Pitfalls
- Letting AI review make a legal redistribution decision. AI can review linguistic/source-curation facts, not rights, credentials, budgets, DB mutation, or publication.
- Treating a complete source-review aggregate as runtime activation. Final generation still needs later provider, DB, Azure, full-run, review, and release evidence.
- Using the review aggregate CLI stdout as the only artifact. Later plans need a stable file, so this plan must serialize `source-review-aggregate.json` explicitly.

## Stop-And-Challenge
    - Stop if review batches cannot be bounded to 100 items, cannot prove AI-policy pass independence/provenance/timestamps/validator roots, or contain private content beyond allowed hashes and controlled codes.
- Stop if final-bundle authority attempts to grant provider, DB, audio, full-run, release, Git, or publication powers.
- Stop if current CLI/service behavior differs from this plan and would require code changes before evidence can be produced.

## Approval Gates
- Source-review AI consensus requires a second pass because it is a high-leverage surface.
- The final-bundle authority requires project-owner/legal approval for the exact local-use and redistribution disposition.
