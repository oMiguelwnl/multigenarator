# Phase 32 Plan 49: Korean Azure Voice Profile Authority

## Objective
Create the narrow authority seam that turns a user/operator-selected voice from the existing live Azure `ko-KR` catalog pilot into a sanitized neutral Korean voice profile artifact, while proving that no audio synthesis, registry activation, review approval, production run, export, release, or delivery authority is granted.

## Context
- Phase 32 success criterion 5 requires an exact live-discovered Azure `ko-KR` voice for approved word and sentence audio with no silent fallback.
- Plan 32-46 produced `live-azure-catalog-result.json` with 16 `ko-KR` voices, one catalog query, zero synthesis attempts, and no downstream authority grants.
- `live-provider-catalog-pilot-evidence.json` explicitly records `grants_voice_profile_authority=false`, so the prior catalog pilot cannot be consumed as profile approval.
- `src/multilang/services/korean_audio.py` already has `KoreanVoiceProfile`, neutral SSML construction, exact audio asset identity, and an unimplemented synthesis seam, but there is no file-authority command that binds a selected catalog voice into a profile artifact.
- `tests/services/test_audio_voice_registry.py` currently requires `SupportedLanguage.KO` to remain absent from the global static voice registry.
- Plan 32-48 proved only disposable/test DB reset and migration rehearsal; it does not provide production DB readiness or audio authority.

## Must-Haves
1. The exact selected voice is explicitly approved by the user/operator and appears in the existing live catalog result with locale `ko-KR`.
2. The created profile binds catalog locator/content hashes, provider policy hash, pilot authority hash, region, voice ID, Azure provider, neutral SSML policy, output format, and both word/sentence usage.
3. Validation proves zero synthesis attempts, zero fallback authority, zero database mutation, and no route/review/export/release/delivery grants.
4. Korean remains absent from the static global voice registry until a separate activation plan.
5. Existing audio integrity/reuse/export gates still require exact synthesized non-fallback bytes and review receipts before any item can advance to audio success or final export.

## Anti-Goals
- No live Azure request, no sample synthesis, no audio bytes, no audio review import/application, no production database use, and no production-scale generation.
- No automatic choice of voice from the catalog by lexical order, first row, documentation preference, or agent judgment.
- No static registry activation for `SupportedLanguage.KO` and no alternate provider/voice fallback.
- No widening into Phase 33 field-level review, Phase 34 observed Anki playback/import evidence, export generalization, release, publication, or delivery.

## Hard Boundaries
- The only allowed catalog source is the existing `live-azure-catalog-result.json` unless execution stops and obtains a new explicit live-catalog plan.
- The profile-authority file can grant only `bind-voice-profile`; it cannot grant `query-catalog`, `synthesize-audio`, `approve-audio`, `apply-review`, `export`, `release`, `publish`, or `deliver` powers.
- If current code's `profile_sample_authority_sha256` semantics are ambiguous, execution must preserve both hashes distinctly in the new artifact and update validators so a sample/authority hash cannot be mistaken for the actual `voice_profile_sha256`.
- File inputs and outputs must be distinct, parent directories must be created only for outputs, and protected input hashes must be checked before and after validation.

## Evidence Contract
- `korean-voice-profile-authority.md` records the user's exact selected voice ID, catalog result file SHA-256, catalog locator/content hashes, provider policy hash, pilot authority hash, locale `ko-KR`, region, neutral SSML policy version, output format, word/sentence scope, `synthesis_allowed=false`, and downstream grants all false.
- `korean-voice-profile.json` is a strict JSON profile artifact containing only sanitized fields needed by future synthesis: schema version, voice ID, locale, region, Azure provider, output format, neutral SSML/profile policy, catalog hashes, authority hash, provider-policy/pilot hashes, and computed profile SHA-256.
- `korean-voice-profile-validation.json` records profile status, selected voice membership, catalog voice count, locale set, profile SHA-256, authority SHA-256, protected-input drift count, synthesis attempt count `0`, fallback policy `none`, static registry activated `false`, and all review/export/release/delivery grants false.
- Focused tests must cover valid binding, wrong selected voice, mixed locale, missing catalog hash, catalog synthesis count greater than zero, output/input path collision, raw content leakage, and `SupportedLanguage.KO` registry rejection.
- Final verification must scan generated profile artifacts and the summary with precise leakage patterns for secrets, provider payloads, private paths, prompt/completion keys, raw DB URLs, generated Korean text bodies, Portuguese text bodies, and audio-byte markers. The plan/summary may contain policy words such as `prompt` and `completion` when describing boundaries, so they must not be scanned with generic word bans.

## Common Pitfalls
- Treating a catalog-listed voice as heard-approved or export-ready.
- Auto-selecting the first catalog voice to avoid the user/operator checkpoint.
- Writing the selected Korean voice into the global fallback registry before profile approval and audio review exist.
- Confusing profile authority hash, profile artifact hash, and future profile-sample/audio-review hashes.
- Recapturing Azure catalog or synthesizing samples while this plan is scoped to offline binding from existing evidence.

## Stop-And-Challenge
- Stop if no exact voice is selected by the user/operator.
- Stop if the selected voice is absent from `live-azure-catalog-result.json` or the catalog evidence has locale/hash/synthesis/grant drift.
- Stop if profile creation requires fields missing from the prior sanitized catalog result and those fields cannot be derived without inventing live Azure payload content.
- Stop if any task would need a live provider call, database mutation, static registry activation, output release, or evidence that exposes secrets/private content.

## Approval Gates
- A user/operator checkpoint is mandatory before `korean-voice-profile-authority.md` and `korean-voice-profile.json` are written with a selected voice.
- A later separate checkpoint is mandatory before any Azure sample synthesis or paid audio run.
- A later separate checkpoint is mandatory before heard/acoustic review application, production database mutation, final export, release, publication, or delivery.
