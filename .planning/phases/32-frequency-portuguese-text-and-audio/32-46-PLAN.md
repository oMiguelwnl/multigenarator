# Phase 32 Plan 46: Live Text And Catalog Pilot

## Objective
Execute the explicitly authorized local live text/catalog pilot for 10 Korean frequency items, then validate the result with row-derived, hash/count-only evidence.

## Context
- `.planning/SPEC.md` keeps Phase 32 in progress and blocks closure until live provider/catalog, production DB, audio, review, export, release, and delivery evidence exists.
- `.planning/ROADMAP.md` Phase 32 requires natural Korean examples, Portuguese text, Azure `ko-KR` discovery, frozen assets, morphology matching, provider telemetry, and no silent fallback.
- `.planning/phases/32-frequency-portuguese-text-and-audio/32-45-SUMMARY.md` recovered only non-closing `pilot_base` command scope and local DB binding; it did not run live provider, DeepL, or Azure calls.
- `.planning/phases/32-frequency-portuguese-text-and-audio/evidence-inbox/pilot-authorization.md` authorizes only a future bounded text/catalog pilot: 10 items, concurrency 1, max attempts 2, no audio synthesis, no fallback, no production DB, and USD 1.00 ceiling.

## Requirements Covered
- KFREQ-03, KTXT-01, KAUD-01, GLEX-01, GLEX-02, GMOR-01, GTXT-01, GPRO-01, GAUD-01

## Must-Haves
1. Local ignored SQLite setup contains exactly 10 grounded candidates from the final frozen Korean frequency bundle.
2. Text pilot executes through the existing Korean text runtime with `--no-synthesize-audio`, no fallback, and sanitized result output.
3. Provider-call rows for live text attempts include sanitized job/item/task/status/latency/hash/token/cost telemetry and the four required evidence hashes.
4. Azure catalog capture performs one authorized `ko-KR` voice-list query and writes sanitized result evidence without audio synthesis.
5. Combined validation passes from DB rows plus protected input hashes and grants no route/profile/audio/review/release/publication authority.

## Anti-Goals
- No audio synthesis, audio review, voice-profile authority, production DB, production full run, field-level review, export, release, publication, delivery, commit, or phase closure.
- No raw generated text, translations, prompts, completions, API keys, database URLs with credentials, or private paths in planning evidence.
- No broad refactor of provider orchestration, Korean selector behavior, or language routing.

## Hard Boundaries
- Use only `.multilang/phase32/pilot/pilot-live-text-catalog.sqlite3` for the live DB; do not mutate `.multilang/phase32/pilot/pilot-base.sqlite3`.
- Leave unrelated dirty worktree changes intact and avoid cleanup/reverts.
- Keep SQLite concurrency at 1 and item count at 10.
- Treat definition/judge route absence from the current batch command as a claim limit, not a reason to add those routes in this plan.

## Evidence Contract
- RED tests must fail before implementation for provider telemetry hashes, candidate setup, and live catalog CLI behavior.
- Targeted offline tests must pass after implementation.
- `git check-ignore --quiet .multilang/phase32/pilot/pilot-live-text-catalog.sqlite3` must pass before local DB mutation.
- Live commands must be run with `.env` loaded without printing secrets.
- Evidence files must be JSON, hash/count-only, and validate with `validate-korean-provider-catalog-pilot-result`.

## Common Pitfalls
- Treating a placeholder catalog command as live discovery.
- Writing raw Azure voice payloads or generated text into planning artifacts.
- Populating provider rows without `route_policy_sha256`, `budget_snapshot_sha256`, `cache_key_sha256`, or `response_schema_sha256`.
- Accidentally enabling audio synthesis through default `--synthesize-audio`.
- Claiming text quality approval or Phase 32 completion from a mechanics-only pilot.

## Stop-And-Challenge
- Stop before live calls if `.env` lacks usable OpenAI/LiteLLM, DeepL, or Azure Speech credentials.
- Stop if the provider policy canonical hash is not `6174ebd73b7e2963285bb2e44205dde10ef9d3917e50c90850b483b3c8a6fc79` or the pilot authority hash is not `db2b2c1bff644ccf2e90bf59ab00d5c4a88c009d1c03bc8e8fbf8146e9be2ced`.
- Stop if Azure catalog capture would need an endpoint outside the credential-backed region or outside `/cognitiveservices/voices/list`.

## Approval Gates
- This plan has existing approval for the bounded local text/catalog pilot only.
- Separate approval is required before synthesis, production database mutation, final review, export, release, publication, delivery, commit, or PR.
