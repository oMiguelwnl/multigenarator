## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lexical source data → domain contracts | External lexical records become learner-facing candidate fields |
| repository writes → live database | Persisted candidate identity and provenance must not drift or duplicate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | T | `src/multilang/domain/lexicon.py` | mitigate | Use explicit typed fields for submitted/display/lemma identities so later services cannot overwrite learner-facing text with raw source strings. |
| T-02-02 | I | `src/multilang/domain/lexicon.py` | mitigate | Encode `definition_language` and `translation_target_language` directly in the contract so downstream phases cannot silently change language policy. |
| T-02-03 | T | `src/multilang/repositories/lexical_repository.py` | mitigate | Enforce a unique `(job_id, item_key)` row and repository upsert path so reruns update one candidate instead of creating duplicates. |
| T-02-04 | R | `tests/repositories/test_lexical_repository.py` | mitigate | Add repository tests proving warning/provenance fields survive updates and pending states remain queryable. |
| T-02-05 | D | live schema | mitigate | Run `uv run alembic upgrade head` before downstream execution so runtime code cannot fail against a stale schema. |
</threat_model>
