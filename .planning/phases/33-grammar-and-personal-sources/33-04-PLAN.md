# Phase 33 Plan 04: Exact Private-Context Authority and Bounded Provider Boundary

<objective>
Require exact one-run authority before bounded private highlight context can reach a fake or configured remote text-generation adapter.

Purpose: KPERS-02 permits useful generated microexamples without turning private reading excerpts into ambient provider context.
Output: Least-privilege capability contracts, local context broker, gated text-generation boundary, and zero-call/privacy tests.
</objective>

## Anti-Goals
- No broad consent flag, ambient provider context, prompt/payload persistence, identity/approval from model text, or live provider call.

## Hard Boundaries
- Exact one-run capability validation, local target-centered bounds, and committed `pending -> disclosing` CAS occur before the adapter call; the call runs outside every database transaction.

## Evidence Contract
- Fake-adapter call counts, reservation/finalization crash tables, replay/concurrency tests, provider-idempotency branches, budget tests, exact-copy rejection, and private-sentinel scans must pass.

## Common Pitfalls
- Treating `allow_private=true` as authority, holding a transaction around a provider callback, auto-retrying an unknown result without provider idempotency, or logging content while building a safe receipt.

## Stop-And-Challenge
- Stop on wildcard/stale authority, binding mismatch, over-budget context, `disclosing|disclosed|failed_unknown` replay, unsafe retry, or inability to prove zero calls on refusal.

## Approval Gates
- A later explicit local command must mint exact authority; no plan or job-level inheritance is permitted.

## Leverage Review
- Lost: implicit context flow and exactly-once assumptions. Kept: typed adapter/sanitizer. Gained: auditable single-use at-most-once disclosure.
