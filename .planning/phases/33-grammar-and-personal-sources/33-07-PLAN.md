# Phase 33 Plan 07: Append-Only Persistence Schema and Migration Join

<objective>
Persist all Phase 33 authorities, private revisions, reviews, and outcomes in one settled-head PostgreSQL migration with ORM parity.

Purpose: The domain contracts are only reliable if persistence prevents hidden drops, copied private values, mutable history, and race-prone pointers.
Output: One Alembic revision, SQLAlchemy mappings, schema tests, and migration parity evidence.
</objective>

## Anti-Goals
- No content asset/backfill-as-accepted, private-value copying, production migration, RLS/auth/API addition, or prior-schema redesign.

## Hard Boundaries
- Create one revision only after an exact single settled Phase 32 head check; immutable evidence tables reject update/delete.

## Evidence Contract
- Catalog, constraint, index, privacy, fresh-upgrade, parity, compatibility, downgrade/re-upgrade, and one-head tests must pass on PostgreSQL.

## Common Pitfalls
- Guessing a down_revision, storing authority in JSON, omitting foreign-key indexes, or allowing ORM cascades to weaken append-only history.

## Stop-And-Challenge
- Stop on unsettled/multiple/unexpected head, revision collision, non-reversible prior-schema impact, or required private duplication.

## Approval Gates
- Only isolated test/local databases may be migrated; production mutation needs separate authorization.

## Leverage Review
- Lost: mutable rows. Kept: Alembic/SQLAlchemy one-head history. Gained: indexed DB-enforced evidence and CAS anchors.
