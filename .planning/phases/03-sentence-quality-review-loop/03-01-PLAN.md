## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated text state → persisted review rows | Meaning-bearing text becomes long-lived learner-facing data |
| repository writes → live database | One job item must not fork into conflicting text rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | T | `src/multilang/domain/text_quality.py` | mitigate | Encode sentence, translation, provenance, and flags as separate typed fields so later services cannot overwrite meaning-bearing text with ad-hoc payloads per D-03 and D-04. |
| T-03-02 | I | `src/multilang/repositories/text_repository.py` | mitigate | Persist structured validation flags and review reasons so low-confidence cards cannot be silently accepted without auditable diagnostics per D-07. |
| T-03-03 | T | `src/multilang/repositories/text_repository.py` | mitigate | Enforce a unique `(job_id, item_key)` row and repository upsert path so item-level regeneration updates one record instead of creating conflicting duplicates per D-09. |
| T-03-04 | D | live schema | mitigate | Run `uv run alembic upgrade head` before later Phase 3 work so runtime code cannot proceed against a stale schema. |
</threat_model>
