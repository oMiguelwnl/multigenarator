# Milestone v1.0: MVP

**Status:** SHIPPED 2026-04-29  
**Phases:** 1-7  
**Total Plans:** 34  
**Total Tasks:** 68 best-effort from phase summaries

## Overview

Multilang v1.0 ships the trust-first CLI/batch foundation for generating Anki-ready multilingual vocabulary cards from supported-language frequency decks or custom word lists. The milestone established durable job orchestration, lexical grounding, text quality review, Azure-first audio, fixed-schema export, and end-to-end evidence that representative custom and frequency inputs can reach accepted text, audio, and `.apkg`/CSV/TSV export.

## Milestone Summary

**Key Accomplishments:**

- Built the `multilang generate` CLI path with supported-language validation, visible progress, resumability, and duplicate-safe reruns.
- Added lexical grounding for frequency decks and custom word lists with deterministic candidate identity, `wordfreq` frequency windows, and cached Kaikki lookup.
- Added text generation, validation, review reports, item-level regeneration, and a filtered Tatoeba secondary fallback path.
- Added Azure-first word and sentence audio synthesis with persistence, reuse, fallback accounting, and live/human verification evidence.
- Added fixed-schema export to `.apkg`, CSV, and TSV with stable note identity, blank `Image`, hidden/revealed `Translation`, and packaged media validation.
- Closed the milestone audit gap by proving representative custom and frequency inputs reach accepted text, audio, and export artifacts end to end.

**Key Decisions:**

- Use Python, uv, typed domain contracts, SQLAlchemy persistence, and service boundaries as the implementation backbone.
- Treat `wordfreq` as deterministic frequency bootstrap and Kaikki/Wiktextract-style lexical data as grounding input rather than relying on LLM-only lexical output.
- Keep Tatoeba as a secondary-only sentence source behind filtering/reranking and validation, never as the raw default source.
- Freeze the export card contract around the requested ten fields and validate Anki behavior with real import/audio checks.
- Use Azure Speech as the primary audio direction with deterministic fallback voice selection and persistent audio metadata.

**Issues Resolved:**

- Restored shipped CLI runtime bootstrap and lifecycle counters.
- Closed stale Phase 1 verification blockers for resume, progress, and duplicate-safe reruns.
- Closed the functional custom/frequency accepted-text-to-export E2E gap.
- Reconciled UAT, quick-task, Phase 5, and Phase 4 validation metadata so the v1.0 audit passes cleanly.

**Issues Deferred:**
